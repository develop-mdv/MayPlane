# Self-hosted MayPlane

Панель для одного владельца. Доступ к панели позволяет управлять подключёнными машинами и разрешениями агентов, поэтому устанавливайте её на доверенный хост с постоянным диском.

## Быстрая установка

Поддерживаются Ubuntu/Debian с systemd, amd64/arm64. Нужен доступ sudo. Node.js 24 и Caddy установщик скачивает из официальных релизов с проверкой контрольных сумм: SHA-256 для Node и SHA-512 для Caddy. Системный Node и существующий веб-сервер не заменяются. Сборка и приложение работают от отдельного пользователя `mayplane`, Caddy — от `mayplane-proxy`.

```sh
curl -fsSL https://raw.githubusercontent.com/develop-mdv/MayPlane/main/scripts/install.sh -o /tmp/mayplane-install.sh && sudo bash /tmp/mayplane-install.sh
```

Альтернатива — клонировать опубликованный репозиторий и выполнить `sudo bash scripts/install.sh`. Из клона устанавливается его текущий коммит `HEAD`; незакоммиченные файлы не копируются. Ветка обновлений — `main`.

Режим можно передать сразу:

```sh
# Без открытия сети
sudo bash scripts/install.sh --mode local

# Доверенный HTTPS по публичному IP
sudo bash scripts/install.sh --mode ip --address YOUR_PUBLIC_IP

# HTTPS по домену с уже настроенными A/AAAA
sudo bash scripts/install.sh --mode domain --address panel.example.com --email admin@example.com
```

`--username owner` задаёт начальный логин. Пароль генерируется криптографически случайно и показывается один раз в терминале, в том числе при ошибке после создания пользователя. Сохраните его в менеджере паролей. Повторная установка сохраняет существующие credentials и ключ базы. Пароли не передаются аргументами команды и не записываются в конфигурацию открытым текстом.

План без sudo, загрузок и записи на диск: `bash scripts/install.sh --mode domain --address panel.example.com --plan`. `--print-caddy` показывает только будущий Caddyfile. Эти режимы не проверяют реальную DNS/доступность адреса; полная проверка выполняется при установке.

## Три режима доступа и сертификаты

| Режим | Адрес | Что открывается |
| --- | --- | --- |
| local | `http://127.0.0.1:8788` | Только loopback. Без выпуска сертификата и входящих сетевых портов |
| ip | `https://YOUR_PUBLIC_IP` | Caddy на TCP 80/443, доверенный сертификат Let's Encrypt для IP |
| domain | `https://panel.example.com` | Caddy на TCP 80/443, автоматический сертификат домена |

Для IP нужен глобально маршрутизируемый IPv4/IPv6, не частный адрес LAN/CGNAT. За NAT перенаправьте TCP 80/443 на этот хост. Для домена все A/AAAA должны указывать на доступный хост панели; ошибочная AAAA может сорвать выпуск даже при рабочей A. Откройте 80/443 также в firewall провайдера/security group. Если UFW уже активен, установщик добавляет эти TCP-порты; он не включает firewall и не меняет правила SSH. Не публикуйте 8788/8789: приложение всегда слушает loopback.

Установщик проверяет занятость портов и не останавливает чужие веб-серверы. Если 80/443 уже заняты, используйте local и свой HTTPS-прокси либо выделите отдельный хост. Публичный HTTP-вход без TLS не поддерживается.

Caddy автоматически получает и продлевает сертификаты, сохраняет ACME-аккаунт и ключи в `/var/lib/mayplane-proxy`. Для IP используется профиль Let's Encrypt `shortlived` (сертификат примерно на 160 часов) и Caddy 2.11.8; служба постоянно следит за обновлением. Отдельный cron или ручной certbot не требуется. Порт 80 и исходящий HTTPS должны оставаться доступными после установки. Не удаляйте хранилище Caddy при обновлениях и резервном копировании.

Установка ждёт успешного `/healthz` через HTTPS с обычной проверкой цепочки и имени сертификата. При ошибке DNS, недоступности ACME или занятых портах сообщает об ошибке и сохраняет данные; HTTP-обход и `--insecure` не включаются. При неудачном обновлении ранее работающей установки скрипт пытается вернуть старую версию и конфигурацию. База автоматически назад не откатывается.

В **Настройки → Доступ к панели** видны состояние сертификата, издатель, дата окончания и управление продлением. Состояние проверяется каждую минуту при открытых настройках; недоступность или близкое окончание показываются явно. Это проверка текущего сертификата, а не обещание будущего успешного ACME-запроса: контролируйте доступность машины и журнал Caddy.

## Вход и восстановление

В настройках можно поменять логин и пароль, подтвердив текущий пароль. Новый пароль — минимум 15 символов. Другие входы и открытые SSH-консоли завершаются; история и аккаунты агентов сохраняются. Выход отзывает только текущую сессию. Активные ходы агентов продолжают работу.

Сессия действует 12 часов; cookie HttpOnly/SameSite=Strict, на HTTPS также Secure. Попытки входа ограничены. Регистрации, ролей и общих командных пространств пока нет. Аккаунты агентов в настройках — отдельная сущность от логина владельца панели.

Восстановление на установленном сервере:

```sh
cd /opt/mayplane/panel/current
sudo -u mayplane env MAYPLANE_ENV_FILE=/etc/mayplane/mayplane.env /opt/mayplane/panel/node/bin/node runner/setup.mjs --reset
```

Команда покажет новый случайный пароль. Все прежние сессии станут недействительны; перезапуск не нужен. Локально: `npm run auth:reset`. Для явно заданного пароля используйте `runner/setup.mjs --reset --password-stdin`, подавая секрет из защищённого источника, без его записи в shell history.

## Данные, проекты и резервные копии

| Путь | Содержимое |
| --- | --- |
| `/opt/mayplane/panel/current` | Ссылка на текущий release, файлы принадлежат root |
| `/opt/mayplane/panel/node` | Частный Node.js 24 для панели |
| `/etc/mayplane/mayplane.env` | Ключ шифрования, origin и режим; root:mayplane, 0640 |
| `/var/lib/mayplane/mayplane.sqlite` | Машины, зашифрованные аккаунты/история, хеш владельца и сессии |
| `/var/lib/mayplane/.mayplane` | Профили агентов хоста панели |
| `/var/lib/mayplane/projects` | Рабочие папки на хосте панели |
| `/var/lib/mayplane/backups` | Согласованные SQLite-копии перед обновлением |
| `/var/lib/mayplane-proxy` | Хранилище сертификатов и ACME Caddy |

**Храните базу вместе с прежним ключом шифрования. Потеря ключа необратима; смена пароля не восстанавливает его.** Перед обновлением установщик делает SQLite backup API-копию без несогласованного копирования живого WAL. Ключ к этой автоматической копии остаётся в существующей конфигурации; отдельно сохраните её вне сервера.

Полная офлайн-копия с минимальным простоем (root, каталог копии приватный):

```sh
sudo bash -c 'set -eu; umask 077; out=/root/mayplane-backup-$(date -u +%Y%m%dT%H%M%S).tar.gz; systemctl stop mayplane mayplane-proxy; trap "systemctl start mayplane; systemctl start mayplane-proxy || true" EXIT; tar -czf "$out" /etc/mayplane /var/lib/mayplane /var/lib/mayplane-proxy; printf "%s\n" "$out"'
```

В local нет службы/каталога прокси: остановите только `mayplane`, копируйте `/etc/mayplane` и `/var/lib/mayplane`, затем запустите `mayplane`. Архив содержит секреты — храните зашифрованно и с доступом только владельцу. Проверяйте восстановление на отдельной машине. Для восстановления остановите службы, верните каталоги с прежними владельцами и правами, затем запустите ту же или совместимую версию. Не смешивайте старую базу с новым ключом.

Для переноса локальной `.runner-data` остановите старую панель, сохраните базу/WAL и `.env.runner`, перенесите прежний ключ в `/etc/mayplane/mayplane.env` и данные в `/var/lib/mayplane`, назначьте владельца mayplane. Профили, рабочие папки и их абсолютные пути переносятся отдельно. Сделайте это **до** запуска установщика, чтобы он не создавал новую пустую базу. Не объединяйте две разные базы.

Хост панели видит собственные рабочие каталоги пользователя `mayplane`, а не домашние файлы root. systemd ограничивает запись каталогом данных и cache, скрывает пользовательские home. Для других рабочих каталогов настройте права и drop-in `ReadWritePaths=` через `systemctl edit mayplane`, затем перезапустите службу. Не давайте всей панели root-права ради доступа к одной папке. Домашние компьютеры подключаются исходящим коннектором WSS, публичный SSH для них не требуется.

## Обновления и диагностика

```sh
sudo bash /opt/mayplane/panel/current/scripts/install.sh --update
sudo systemctl status mayplane mayplane-proxy
sudo journalctl -u mayplane -u mayplane-proxy -n 100
sudo -u mayplane env MAYPLANE_ENV_FILE=/etc/mayplane/mayplane.env /opt/mayplane/panel/node/bin/node /opt/mayplane/panel/current/runner/doctor.mjs
```

Обновление сохраняет login/password, ключ базы и хранилище TLS, собирает отдельный release и переключает ссылку после сборки. Перед обновлением завершите активные ходы и консоли: перезапуск прерывает процессы агентов, самоповтора запросов нет. Коннекторы обновляйте из той же версии отдельно. Изменить режим можно повторным запуском с `--mode ... --address ...`; хранилище данных остаётся прежним.

Локальная установка на Windows/macOS/Linux: `npm ci`, `npm run runner:setup`, `npm run build`, `npm start`. Внешний доступ не открывается. Режим разработки — отдельные `npm run runner` и `npm run dev -- --port 3000`; публикуйте production-сборку.

## Собственный reverse proxy

В local-установке задайте в `/etc/mayplane/mayplane.env` `MAYPLANE_PUBLIC_URL=https://panel.example.com`, `MAYPLANE_TRUST_PROXY=true`, `MAYPLANE_TLS_MANAGED=false` и перезапустите mayplane. Собственный прокси должен работать на том же хосте и проксировать на `127.0.0.1:8788`, принудительно устанавливая `X-Forwarded-Proto: https` и достоверный клиентский адрес. Origin — ровно указанный URL. Установите доверенный сертификат с автопродлением средствами своего прокси.

Пропускайте WebSocket и Authorization для `/api/connector`; не заменяйте его владельческой авторизацией и не закрывайте этот маршрут браузерной SSO-формой. SSH-консоли используют браузерную cookie и одноразовый билет. Если прокси находится на другом хосте, используйте защищённый локальный туннель; менять bind на `0.0.0.0` приложение не позволяет.

Источники: [автоматический HTTPS Caddy](https://caddyserver.com/docs/automatic-https), [IP и короткоживущие сертификаты Let's Encrypt](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability).
