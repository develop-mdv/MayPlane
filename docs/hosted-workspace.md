# Размещённая панель и личные машины

Постоянная серверная часть панели хранит проекты, зашифрованную историю, аккаунты и реестр машин. Браузер — клиент: закрытие вкладки не останавливает начатый через панель ход. С другого устройства владелец открывает тот же сайт и тот же чат. Файлы и процессы остаются на машине проекта.

## Подключения

- **Хост панели** — ОС, где запущен Node runner. «Подключить машину → Хост панели» регистрирует её один раз без SSH. Это не компьютер посетителя сайта. Если runner в контейнере, доступны только его файловая система, смонтированные папки и установленные в нём агенты, а не весь физический VPS.
- **ПК, Mac mini или локальный сервер** — исходящий коннектор WSS, работающий за NAT без входящих портов. Windows, macOS, Linux. Для работы машина должна быть включена и иметь интернет.
- **SSH-сервер** — проверенный SSH. Для частной сети runner должен иметь маршрут, например VPN; иначе используйте коннектор на самой машине.

Коннектор запускает агентов от своего пользователя. Используйте обычный профиль с нужными папками и установленными агентами. Подключение означает доверие к серверной части панели: WSS защищает транспорт, но не ограничивает администратора панели или взломанный runner.

## Домашний компьютер

В панели задайте имя машины. Адрес подключения определяется автоматически и недоступен для ручного редактирования: сначала используется настроенный публичный URL, затем адрес отдельного API, затем origin сайта в браузере. Домен, IPv4/IPv6 и порт сохраняются; HTTPS превращается в WSS. Удалённое подключение по IP тоже требует HTTPS с доверенным сертификатом. HTTP разрешён только для loopback-проверки. Код подключения действует пять минут и используется один раз. Успешное сопряжение подтверждается автоматически; кнопка нового кода отменяет предыдущий код из этого окна.

На компьютере нужен Node.js 24+:

```sh
git clone https://github.com/develop-mdv/ezdeploy.git
cd ezdeploy
npm ci
npm run connector -- --url https://panel.example.com --pair
```

Код вводится интерактивно. Постоянный ключ сохраняется в `~/.ezdeploy-connector/connection.json` с пользовательскими правами и не попадает в argv. Повторный запуск — `npm run connector`. Отдельный профиль — `--data-dir`. Отзыв в панели инвалидирует ключ; повторный вход требует нового кода.

После проверки остановите ручной процесс (Ctrl+C), затем:

```sh
npm run connector -- --install-service
```

Автозапуск использует задачу Планировщика Windows, LaunchAgent macOS или systemd user unit Linux. Без пароля ОС и повышения прав; тот же пользователь и ключ. Windows/macOS требуют входа пользователя в ОС. Для Linux без интерактивного входа отдельно настройте systemd user manager/linger. Коннектор переподключается после потери сети, но не будит выключенную/спящую машину. Для Mac mini настройте питание и сон средствами macOS.

Отключение автозапуска: `npm run connector -- --uninstall-service`. Шаблоны трёх ОС проверяются тестами; реальную установку службы следует проверять на целевой ОС. Обновление пока ручное: `git pull`, `npm ci`, перезапуск службы.

## Продолжение из CLI и настольного Codex

«Чаты → Продолжить с компьютера» показывает сохранённые диалоги пользователя агента. Продолжение использует тот же нативный ID и исходную папку. История шифруется в панели, файлы не копируются. Проект подбирается по уже добавленной папке; иначе чат находится без проекта. Перед отправкой история перечитывается; также есть кнопка «Синхронизировать».

Codex использует app-server `thread/list`, `thread/read`, `thread/items/list`, `thread/resume`, со старым форматом — `includeTurns`. Для нового формата истории настольного приложения в Windows выбирается CLI установленного пакета Codex, в macOS — CLI из `/Applications/Codex.app/Contents/Resources/codex` или `~/Applications`. Явный `EZDEPLOY_CODEX_BIN` имеет приоритет. При отдельном `CODEX_HOME` запускайте коннектор с тем же профилем. Облачные чаты, отсутствующие на компьютере, не скачиваются. Для больших диалогов отображаются последние 100 элементов истории; полный контекст остаётся у агента.

OpenCode использует ACP `session/list` и `session/load` с реплеем. Нужен агент с этими capabilities, рекомендуется OpenCode 2. Перед переходом завершите ход в исходном CLI/приложении. Два клиента не должны одновременно отправлять сообщения в один диалог: межпроцессной транзакционной синхронизации нет. Чужой процесс панель автоматически не захватывает и не останавливает. Импортированный чат использует профиль машины; для аккаунта панели создайте отдельный чат. Оборванный ход автоматически не повторяется.

## Локальные модели

Провайдер локальной модели настраивается в OpenCode/Codex на самой машине. `localhost` домашнего агента означает домашний ПК, а не VPS панели. В новом чате выбирайте «Аккаунт машины», чтобы сохранить эти настройки. Каталог берётся из агента; inference не переносится на хост панели, API модели публиковать не требуется. Установка моделей, Ollama/LM Studio и GPU пока управляются на самой машине. История при подключении диалога передаётся на сервер панели — локальная модель не означает отсутствие данных на сервере управления.

## Будущее размещение сайта

Фронтенд и Node runner — два компонента за HTTPS. Runner требует постоянный диск SQLite, прежний ключ шифрования, WebSocket и запуск процессов/SSH; edge-функция не заменяет его. В `.env.runner` задайте `EZDEPLOY_PUBLIC_URL=https://panel.example.com` и точный `ALLOWED_ORIGINS`. Панель предложит правильный WSS-адрес; недоверенный заголовок Host для этого не используется.

До публикации нужен вход владельца через защищённый reverse proxy/SSO либо VPN. Текущая версия — одно личное пространство с административным bearer token. Для многопользовательского SaaS нужны отдельные user/workspace IDs и проверки владельца во всех маршрутах машин, аккаунтов, чатов и сопряжения; это отдельный этап.

Reverse proxy должен разделять браузерный API и `/api/connector`: коннектор передаёт свой Authorization, его нельзя заменять административным токеном или закрывать браузерной формой SSO. Браузерный UI/API остаётся за входом владельца. Dev-сервер с автоматической подстановкой административного токена публиковать нельзя. Бэкап включает SQLite и отдельное хранение ключа шифрования. Перенос хоста панели не переносит файлы домашних машин.

Протоколы: [Codex app-server](https://learn.chatgpt.com/docs/app-server), [OpenCode ACP](https://dev.opencode.ai/v2/docs/cli/acp/).
