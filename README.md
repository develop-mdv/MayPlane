# ezdeploy

Личное веб-пространство для проектов, диалогов с **Codex / OpenCode** и управления машинами. Linux-серверы разных провайдеров, локальный компьютер и домашний ПК доступны в одном интерфейсе.

## Основной сценарий

1. В **Серверы** подключите Linux-машину по SSH, добавьте компьютер runner или создайте код для исходящего коннектора.
2. Откройте карточку машины: установите агент и войдите в свой аккаунт. Для Codex доступен device-code вход ChatGPT прямо из панели.
3. В **Проекты** добавьте существующую рабочую папку на машине.
4. Создайте диалог, выберите Codex/OpenCode, при необходимости модель и режим доступа. Переписка, команды, изменения файлов, запросы разрешений и остановка доступны в одном чате.

Серверы: CPU/RAM/диск, график сети Linux, IPv4/IPv6, копирование SSH-команды и значений, временный показ пароля, SSH-терминал, ссылка на VNC/консоль провайдера. Показатели и история измерений реальные, без демонстрационных значений. Поиск пространства: **Ctrl/Cmd + K**. Диалоги можно переименовать и архивировать. В SSH-консоли Ctrl+C копирует выделение, а без выделения прерывает команду; Ctrl+V вставляет через штатный механизм терминала. История вывода прокручивается внутри консоли.

## Локальный запуск

Нужен Node.js **24+**.

```sh
npm ci
npm run runner:setup
```

Запустите два процесса из корня проекта:

```sh
npm run runner
npm run dev -- --port 3000
```

Откройте [127.0.0.1:3000](http://127.0.0.1:3000). Панель подключается к runner через локальный прокси. `.env.runner` содержит ключи доступа/шифрования; не публикуйте его. Данные остаются в `.runner-data/ezdeploy.sqlite`.

Не меняйте `EZDEPLOY_ENCRYPTION_KEY` у существующей базы: без прежнего ключа её секреты не расшифровать. Для резервной копии используйте SQLite backup API или остановите runner и копируйте базу вместе с WAL/SHM при их наличии; ключ храните отдельно.

Для запуска не из стандартного PATH можно задать абсолютные пути `EZDEPLOY_CODEX_BIN` и `EZDEPLOY_OPENCODE_BIN`. Установка выполняется по явной кнопке подтверждения. OpenCode на Linux/macOS устанавливается официальным native-установщиком в `~/.opencode/bin` без Node/npm; существующая версия и запущенные службы сохраняются. Codex и OpenCode на Windows устанавливаются через npm. Для Codex на Linux/macOS используется пользовательский prefix `~/.local`. Панель также находит native-установки и Node из NVM без загрузки `.bashrc`. Для SSH рекомендуем отдельного пользователя, а не root.

## Домашний ПК без входящих портов

В панели: **Серверы → Подключить ПК → создать код**. На компьютере с копией репозитория и установленными зависимостями:

```sh
npm run connector -- --url wss://control.example.com/api/connector --pair
```

Вставьте одноразовый код по запросу CLI. Он действует 5 минут. Коннектор сохраняет свой отдельный ключ в `~/.ezdeploy-connector/connection.json`; флаг `--pair` принудительно начинает новое сопряжение. При последующих запусках достаточно `npm run connector` либо того же адреса без `--pair`.

Адрес панели должен быть доступен с компьютера по WSS. Для проверки на одной машине допустим `ws://127.0.0.1:8788/api/connector`. Работают Windows, macOS, Linux. При отзыве подключения в карточке машины старый ключ перестаёт работать. Коннектор должен оставаться запущенным; автоматическая установка системной службы пока не выполняется.

## Аккаунты и разрешения

- **Codex:** штатный app-server и персональная авторизация на выбранной машине. Device-code вход не требует перенаправления браузера на localhost удалённого сервера. Модель по умолчанию берётся из агента; доступны `read-only` и `workspace-write`, дополнительные права запрашиваются в чате.
- **OpenCode:** штатный ACP-процесс и провайдеры, настроенные на машине. Вход запускает `opencode auth login`; если CLI требует интерактивного меню, используйте встроенную SSH-консоль. Вход для локального ПК можно завершить штатным CLI на нём. Инструменты запрашивают разрешение, интерфейс выдаёт его на одно действие.
- **Claude Code:** пока не подключён; адаптер можно добавить в эту же модель машин и диалогов.

История и названия диалогов зашифрованы в SQLite. Токены аккаунтов агентов остаются в их штатных хранилищах на машинах. Это приложение для одного владельца; E2E-шифрование, команды пользователей и RBAC пока не реализованы.

## Удалённое размещение

Runner по умолчанию слушает `127.0.0.1:8788`. Используйте HTTPS reverse proxy с аутентификацией владельца или VPN. Не выставляйте локальный dev-прокси с автоматически подставляемым административным токеном в публичный интернет. `ALLOWED_ORIGINS` должен содержать точные адреса вашей панели.

Фронтенд можно собрать командой `npm run build`; `npm start` запускает собранный Worker локально через Wrangler. Dev-прокси `/api` существует только в `npm run dev`: для собранного фронтенда настройте API-прокси на своём reverse proxy либо подключите HTTPS API и токен в **Настройках**. Путь `/api/connector` должен поддерживать WebSocket и пропускать отдельную авторизацию коннектора. Нельзя подменять её административным токеном.

## Обновление прежнего проекта

Существующие серверы, пароли и проекты сохраняются. Проекты автоматически появляются как рабочие папки; для управляемых развёртываний используется `/opt/ezdeploy/<id>/repo`, для привязанных приложений — исходная папка. Проверьте путь перед первой задачей.

Мастер деплоя, переносы и root-LLM-оператор убраны из основного интерфейса. Их старый API и webhooks отключены в обычном runner; обратное включение — только `EZDEPLOY_LEGACY_API=true`. Код и данные сохранены для обратимости. Прежняя документация: [docs/legacy-deployment.md](docs/legacy-deployment.md).
