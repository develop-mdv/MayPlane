# MayPlane

Личное веб-пространство для проектов, диалогов с **Codex / OpenCode / Claude Code** и управления машинами. Linux-серверы разных провайдеров, локальный компьютер и домашний ПК доступны в одном интерфейсе.

## Основной сценарий

1. В **Серверы** подключите Linux-машину по SSH, добавьте компьютер runner или создайте код для исходящего коннектора.
2. Откройте карточку машины и установите агент. В **Настройки → Аккаунты агентов** добавьте личный или рабочий аккаунт Codex/OpenCode либо Anthropic API-ключ для Claude Code и назначьте его машине. Для подписки Claude нажмите **Подключить подписку Claude** в тех же настройках.
3. В **Проекты** добавьте существующую рабочую папку. Нажмите **Выбрать папку**, чтобы открыть каталоги на выбранной машине. Полный путь можно ввести вручную.
4. Создайте чат в проекте или выберите **Без проекта**, машину и, при необходимости, рабочую папку. Выберите Codex/OpenCode/Claude Code, модель и режим доступа. Чаты сгруппированы по папкам в боковой панели; доступны переименование, архив, поиск и перенос в проект на той же машине.

В проекте и в чате кнопка **Файлы** открывает дерево рабочей папки и предпросмотр текста. Во вкладке **Git** видны текущие незакоммиченные изменения: в индексе, в рабочей копии и новые файлы. Для вкладки **Правки агента** панель сравнивает рабочую папку до и после запроса и сохраняет правки из отчёта агента. Так видны и изменения через команды в папке без Git. Сравнение пропускает папки зависимостей и некоторые файлы с секретами. Просмотр не изменяет файлы и индекс. Для удалённого SSH-сервера нужен SFTP, для подключённого компьютера нужен обновлённый коннектор.

Серверы: CPU/RAM/диск, график сети Linux, IPv4/IPv6, копирование SSH-команды и значений, временный показ пароля, SSH-терминал, ссылка на VNC/консоль провайдера. Показатели и история измерений реальные, без демонстрационных значений. Поиск пространства: **Ctrl/Cmd + K**. Диалоги можно переименовать и архивировать. В SSH-консоли Ctrl+C копирует выделение, а без выделения прерывает команду; Ctrl+V вставляет через штатный механизм терминала. История вывода прокручивается внутри консоли.

**Лимиты агента** доступны рядом с выбором аккаунта и модели в чате, при создании чата и переключении аккаунтов. Codex показывает остаток каждого полученного окна, дату и время сброса, дополнительные кредиты и число доступных сбросов. Данные относятся к выбранному аккаунту, автоматически обновляются и доступны для ручного обновления. Запросы лимитов не запускают модель. Для API-ключей и агентов без такого интерфейса панель явно сообщает об отсутствии данных. OpenCode через ACP передаёт размер занятого контекста и стоимость чата, когда версия агента их поддерживает; это отдельные показатели, а не остаток подписки.

Под полем сообщения нажмите **Инструменты**, чтобы открыть два независимых переключателя. Оба выключены по умолчанию и сохраняются отдельно для каждого чата.

- **Harness²** добавляет к следующему ходу метод из [Harness²](https://github.com/google-research/harness2). Выбранный агент сравнивает подходы на доступных проверках и выполняет итоговый вариант одним штатным ходом. Панель сохраняет короткие наблюдения, если указанный фрагмент есть в выводе успешно завершившегося инструмента. Наблюдения доступны следующим ходам этого чата в той же рабочей папке. Режим работает с Codex, OpenCode и Claude Code, включая `/services`.
- **Автоаппрув** после явного включения одобряет поддерживаемые одноразовые запросы инструментов, в том числе запросы на запуск команд и расширение доступа. Агент может изменить данные или запущенные сервисы. Вопросы пользователя и разрешения без одноразового варианта по-прежнему требуют ответа. Отключить режим можно во время хода. Ранее одобренные действия могут продолжить выполнение.

В карточках серверов и компьютеров видны занятые/общие объёмы RAM и диска, доступное место и загрузка в vCPU. На графиках можно выбрать последние 5/15 минут или все сохранённые замеры, посмотреть значение и время указателем, касанием или стрелками. Входящий и исходящий сетевые потоки переключаются в легенде. История содержит до 120 измерений; старые замеры без абсолютных объёмов не дополняются расчётными значениями. Для новых полей метрик домашнего ПК обновите и перезапустите его коннектор.

В **Сервисы → Добавить сервис** можно описать приложение вручную или нажать **Найти на сервере** и выбрать существующий контейнер, компонент Docker Compose или службу systemd. Карточку можно связать с рабочим проектом на любой машине. Панель показывает состояние, доступные метрики и журнал выбранного источника. Для HTTP-проверки укажите адрес внутри машины, например `http://127.0.0.1:8080/health`.

**Оформить сервис** собирает сведения об источнике и манифестах и заполняет черновик карточки через Codex на хосте панели. Подходит локальный вход Codex или аккаунт Codex, назначенный хосту в разделе **Серверы**. Проверьте предложенные поля и нажмите **Сохранить сервис**.

Чтобы оформить несколько сервисов, выберите **Инструменты → Оформить сервисы** в чате или введите `/` и выберите `/services` клавишей Tab или Enter. Команда появится отдельной меткой. Допишите задачу или сразу отправьте команду, чтобы начать с осмотра машины. Работает выбранный в чате агент с его моделью и доступами. Ссылку на Git-репозиторий и ответы на уточнения можно прислать в том же диалоге.

В ответе агента отметьте нужные карточки и нажмите **Сохранить выбранное**. У сервиса с несколькими компонентами, например сайтом и API, источник выбирается во вкладке **Логи**.

**Новый чат** в карточке сервиса открывает диалог в указанном каталоге. Если этот каталог уже добавлен как проект на той же машине, новый чат попадёт в проект. Вкладка **Чаты и проекты** показывает совпадения по машине и каталогу, а также явно связанный проект и чаты сервиса.

В разделе **Поля и метрики** нажмите **Настроить в чате** и опишите, что важно для приложения. Карточку можно выбрать под полем сообщения в любом чате, в том числе на другой машине. Агент может предложить ссылки, цветные метки, заметки, копируемые значения и собственные разделы со списком или сеткой. Эти элементы можно добавлять и при создании карточки через `/services`. Кнопка **Применить к карточке** сохранит черновик.

Метрики поддерживают пороги и несколько локальных JSON-эндпоинтов на машине сервиса. Например, можно показать длину очереди из поля `queue.waiting` рядом с нагрузкой на CPU из мониторинга Docker. Живые значения доступны для SSH-машин и хоста панели. Для коннекторов доступны поля и разделы.

## Быстрый старт на сервере

Ubuntu/Debian с systemd, amd64 или arm64. Установщик предложит **локальный доступ**, **публичный IP с HTTPS** или **домен с HTTPS**, выдаст логин и случайный пароль, настроит службы и автопродление сертификатов.

```sh
curl -fsSL https://raw.githubusercontent.com/develop-mdv/MayPlane/main/scripts/install.sh -o /tmp/mayplane-install.sh && sudo bash /tmp/mayplane-install.sh
```

Для просмотра перед запуском скачайте скрипт и выполните `bash /tmp/mayplane-install.sh --help` или `--plan`. Из клона репозитория: `sudo bash scripts/install.sh`. Скрипт устанавливает последнюю опубликованную версию; установка из клона использует его `HEAD`.

Для IP/домена нужны свободные и доступные извне TCP-порты **80 и 443**; для домена заранее настройте все A/AAAA-записи. Caddy получает доверенный сертификат и автоматически продлевает его, включая короткоживущие сертификаты IP. Установщик проверяет настоящий HTTPS без отключения проверки сертификата. Посторонние сайты на занятых портах не останавливаются.

Смена логина/пароля и статус сертификата находятся в **Настройки → Доступ к панели**. Подробности, обновление, восстановление доступа, резервные копии и собственный reverse proxy: [docs/self-hosting.md](docs/self-hosting.md).

## Локальный запуск

Нужен Node.js **24+**.

```sh
npm ci
npm run runner:setup
```

Соберите и запустите приложение одной командой запуска:

```sh
npm run build
npm start
```

Откройте [127.0.0.1:8788](http://127.0.0.1:8788) и войдите с данными, выданными `runner:setup`. Порты 8788/8789 слушают только loopback. Данные остаются в `.runner-data/mayplane.sqlite`; `.env.runner` содержит ключ шифрования, его нельзя публиковать.

Для разработки с горячим обновлением запустите API и dev-сервер в двух терминалах:

```sh
npm run runner
npm run dev -- --port 3000
```

Адрес разработки: [127.0.0.1:3000](http://127.0.0.1:3000). Вход тот же; dev-прокси больше не подставляет административный токен.

Не меняйте `MAYPLANE_ENCRYPTION_KEY` у существующей базы: без прежнего ключа её секреты не расшифровать. Для резервной копии используйте SQLite backup API или остановите runner и копируйте базу вместе с WAL/SHM при их наличии; ключ храните отдельно.

Для запуска не из стандартного PATH можно задать абсолютные пути `MAYPLANE_CODEX_BIN` и `MAYPLANE_OPENCODE_BIN`. Установка выполняется по явной кнопке подтверждения. На Linux/macOS оба агента устанавливаются официальными native-установщиками без Node/npm: Codex — в `~/.local/bin`, OpenCode — в `~/.opencode/bin`. Установщик Codex работает без интерактивных вопросов, проверяет загрузку и поддерживает обновление; OpenCode сохраняет уже работающую установку. Настройки и аккаунты сохраняются. На Windows используется npm. Панель находит пользовательские установки без загрузки `.bashrc`, отдельно проверяет версию CLI и готовность аккаунта/протокола, автоматически повторяет проверку после успешной установки. Для SSH рекомендуем отдельного пользователя, а не root.

Модели выбираются из списка с поиском при создании чата и под полем сообщения в существующем чате. Каталог приходит от агента на выбранной машине с учётом рабочей папки и аккаунта: Codex — `model/list` со всеми страницами, OpenCode и Claude — ACP config options (для старых версий — ACP models). Уровни reasoning показываются только из возможностей выбранной модели. Пока открыт выбор, список обновляется каждую минуту; кнопка «Обновить» перечитывает его сразу. Установка остаётся настройкой машины; доступ к провайдерам определяется выбранным аккаунтом. Каталог моделей не гарантирует права аккаунта на каждый запрос.

Claude устанавливается вместе с закреплённым `@agentclientprotocol/claude-agent-acp@0.100.0` в `~/.mayplane/agents/claude/`. Адаптер использует официальный Claude Agent SDK с собственным Claude Code. На Linux/macOS дополнительно проверяется штатный CLI; при отсутствии Node.js 22+ и npm загружается отдельный Node.js 24 с проверкой SHA-256. Работающий штатный CLI и его авторизация сохраняются. На Windows используется npm текущего Node.js, глобальная установка не нужна; для работы Claude требуется Git for Windows. Для нестандартных установок доступны `MAYPLANE_CLAUDE_BIN` (CLI) и `MAYPLANE_CLAUDE_ACP_BIN` (ACP-исполняемый файл).

## Домашний ПК без входящих портов

В разделе **Серверы** откройте **Подключить компьютер** и создайте код сопряжения. На компьютере с копией репозитория и установленными зависимостями:

```sh
npm run connector -- --url wss://control.example.com/api/connector --pair
```

Вставьте одноразовый код по запросу CLI. Он действует 5 минут. Коннектор сохраняет свой отдельный ключ в `~/.mayplane-connector/connection.json`; флаг `--pair` принудительно начинает новое сопряжение. При последующих запусках достаточно `npm run connector` либо того же адреса без `--pair`.

Адрес панели должен быть доступен с компьютера по WSS. Для проверки на одной машине допустим `ws://127.0.0.1:8788/api/connector`. Работают Windows, macOS, Linux. При отзыве подключения в карточке машины старый ключ перестаёт работать. Коннектор должен оставаться запущенным. После сопряжения доступен пользовательский автозапуск: `npm run connector -- --install-service`; отключение — `--uninstall-service`.

Подключение хоста панели, продолжение из CLI/настольного Codex, локальные модели и схема будущего хостинга описаны в [docs/hosted-workspace.md](docs/hosted-workspace.md).

## Аккаунты и разрешения

- **Codex:** в настройках добавьте аккаунт через **Войти с ChatGPT** (ссылка и код устройства) или OpenAI API-ключ. Можно хранить несколько аккаунтов с разными названиями. На машине панели должен быть установлен актуальный Codex. На сервер передаётся access token через app-server; refresh token остаётся в зашифрованном хранилище панели. Доступны `read-only` и `workspace-write`, дополнительные права запрашиваются в чате.
- **OpenCode:** выберите провайдера и предлагаемый им способ OAuth или API-ключ. Список провайдеров и способов входа загружается из OpenCode, установленного на машине панели. Рекомендуется OpenCode 2; OpenCode 1 на целевых серверах поддерживается для совместимых способов входа. Для OpenAI на старом сервере выбирайте **Codex device code (legacy)**, а не token sharing. Инструменты запрашивают разрешение на одно действие.
- **Claude Code:** в настройках можно сохранить несколько именованных **Anthropic API-ключей**, назначать их машинам и переключать в остановленном чате. Ключи зашифрованы, передаются в отдельный профиль чата и удаляются с машины после хода. Для штатного аккаунта выберите **Серверы → машина → Claude Code → Войти в Claude Code на этой машине**, откройте ссылку и при необходимости вставьте код обратно в панель. Такой вход меняет обычный профиль Claude Code выбранного пользователя ОС; в чатах выберите **Аккаунт машины**. Выход доступен в той же карточке. Процесс входа можно остановить или продолжить после перехода между разделами. Подписочная сессия не переносится между машинами: встроенный Claude.ai OAuth в стороннем SDK-продукте требует [отдельного одобрения Anthropic](https://code.claude.com/docs/en/agent-sdk/overview). Используются штатные разрешения Claude; запросы ACP показываются в чате, постоянные разрешения панель не выдаёт. Это не OS-песочница; настройки пользователя, проекта и MCP остаются доверенными.

Для своей подписки откройте **Настройки → Аккаунты агентов → Подключить подписку Claude** (либо **Добавить аккаунт → Claude Code → Войти с подпиской Claude**). Выберите машину, установите Claude и адаптер, если они отсутствуют, и нажмите **Войти с подпиской Claude**. В браузере войдите в свой Claude-аккаунт; если CLI запросил код, вставьте его в форму панели. После проверки нажмите **Использовать подписку для новых чатов**. API-ключ не требуется; новые чаты этой машины используют **Подписка / профиль Claude на машине**. Панель проверяет именно нативный вход и не принимает API-ключ за подписку. Если на машине в окружении или настройках CLI явно задан API-ключ, уберите его, чтобы Claude не использовал API вместо подписки.

Подписка остаётся в штатном профиле пользователя выбранной машины и не копируется в vault или на другие машины. **Сменить аккаунт Claude** запускает новый штатный вход после завершения активных чатов; профиль общий для всех чатов этой машины, использующих нативный аккаунт. Уже созданные чаты с API-аккаунтом не переключаются на подписку автоматически. Если нужно использовать подписку рядом с такими чатами, создайте новый чат с профилем машины.

Аккаунт машины по умолчанию применяется только к новым чатам. В существующем чате откройте **Инструменты** под полем сообщения и выберите аккаунт. Переключение доступно после завершения хода и сохраняет нативную историю. Для старого чата, созданного со штатным профилем машины и уже получавшего ответы, создайте новый чат с аккаунтом панели. Неподключённые Codex и Claude отклоняют отправку до сохранения сообщения, а черновик остаётся при переходе в настройки в этой вкладке.

Для каждого чата с аккаунтом панели создаётся отдельный профиль в `~/.mayplane/agent-profiles/`; обычная авторизация CLI не меняется. Выбор **Аккаунт машины** использует штатный профиль пользователя ОС. OpenCode OAuth допускает один активный чат на аккаунт, чтобы не конфликтовали вращающиеся refresh tokens между серверами; API-ключи поддерживают параллельную работу. После хода OpenCode обновлённые токены возвращаются в зашифрованное хранилище, а их копия на машине удаляется. При разрыве связи панель восстанавливает обновлённые credentials перед следующим использованием. Отключение аккаунта очищает секреты панели и профилей; для недоступной машины удаление ставится в очередь до её подключения. Сам профиль и история чата сохраняются.

История, названия диалогов и credentials аккаунтов зашифрованы в SQLite. API никогда не возвращает ключи, access/refresh tokens в браузер. OAuth завершается на странице провайдера; пароль от аккаунта панель не запрашивает. Для подключённых ПК обновите код коннектора и перезапустите его, чтобы появились операции профилей. Это приложение для одного владельца; E2E-шифрование, команды пользователей и RBAC пока не реализованы.

В **Настройки → Аккаунты агентов** доступны **Отключить** и **Удалить**. Отключение оставляет карточку для повторного входа. Удаление с подтверждением убирает запись и сохранённые секреты, отменяет незавершённую авторизацию и снимает аккаунт с настроек машин. Чаты, нативная история, проекты и файлы сохраняются; существующие чаты попросят выбрать другой аккаунт. Удаление во время активного хода или подготовки доступа запрещено. Копии credentials в профилях очищаются в фоне, в том числе после повторного подключения недоступных машин; очередь сохраняется при перезапуске, даже когда самой карточки аккаунта уже нет. Аккаунт у провайдера не удаляется.

## Удалённое размещение

Используйте установщик из быстрого старта. `npm start` управляет API и production-рендерером как одним приложением. Внешний доступ обслуживает отдельная служба Caddy с HTTPS, редиректом HTTP и автоматическим продлением. API и рендерер остаются на loopback; панель работает от пользователя `mayplane`, прокси — от отдельного `mayplane-proxy` без доступа к базе и ключу.

Вход владельца хранится как scrypt-хеш; браузер получает HttpOnly/SameSite cookie с ограниченным сроком. Пароль можно изменить в настройках или восстановить на хосте через `npm run auth:reset`. Старый `MAYPLANE_TOKEN` больше не даёт вход в запущенную панель. Подключённые ПК используют собственные отзываемые токены WSS; этот канал не требует браузерной cookie.

## Обновление прежнего проекта

Прежние развёртывания называются **Сервисами** и находятся в отдельном разделе. Их серверы, настройки и секреты сохраняются. **Проекты** — только явно добавленные рабочие папки агентов. Автоматически импортированные раньше папки сервисов убираются из проектов; связанные чаты переходят в **Без проекта**, сохраняя историю, нативный ID и прежний рабочий каталог. Новые чаты без проекта начинают работу в домашнем каталоге выбранной машины; Codex по умолчанию использует только чтение. Удаление проекта из списка не удаляет папку и файлы: его чаты остаются без проекта.

Мастер деплоя, переносы и root-LLM-оператор убраны из основного интерфейса. Их старый API и webhooks отключены в обычном runner; обратное включение — только `MAYPLANE_LEGACY_API=true`. Код и данные сохранены для обратимости. Прежняя документация: [docs/legacy-deployment.md](docs/legacy-deployment.md).

## Удаление объектов

У чата в меню `…` есть отдельное действие **Удалить чат**, доступное также в архиве. Оно удаляет историю из MayPlane; нативная история агента на машине сохраняется.

Проект можно удалить из бокового меню или карточки. По умолчанию его чаты остаются в **Без проекта** с прежней рабочей папкой; в подтверждении можно выбрать удаление всех чатов проекта, включая архивные. Сервис удаляется кнопкой в его карточке: работа приложения, контейнеры и файлы на сервере сохраняются.

Кнопка удаления машины находится в её карточке. Подтверждение показывает количество связанных проектов, чатов и сервисов: они удаляются вместе с подключением из панели. Для удаления связанных данных нужно ввести название машины. Коннектор теряет доступ, SSH-консоли закрываются; сама машина и её файлы остаются. Сохранённые общие аккаунты агентов в настройках не удаляются. Если на машине остаются копии credentials, требуется отдельное подтверждение удаления без их очистки.

Активные чаты нужно остановить; установки, вход агента и переносы сервисов — завершить. Состав удаления проверяется повторно перед записью, а изменения базы выполняются одной транзакцией. Копии доступа удалённого чата очищаются из его изолированного профиля, для недоступной машины очистка ожидает подключения. Папки проектов и штатные профили CLI не удаляются.
