# MayPlane

Личное веб-пространство для проектов, диалогов с **Codex / OpenCode** и управления машинами. Linux-серверы разных провайдеров, локальный компьютер и домашний ПК доступны в одном интерфейсе.

## Основной сценарий

1. В **Серверы** подключите Linux-машину по SSH, добавьте компьютер runner или создайте код для исходящего коннектора.
2. Откройте карточку машины и установите агент. В **Настройки → Аккаунты агентов** добавьте личный или рабочий аккаунт Codex/OpenCode и назначьте его машине.
3. В **Проекты** добавьте существующую рабочую папку на машине.
4. Создайте чат в проекте или выберите **Без проекта** и машину. Выберите Codex/OpenCode, при необходимости модель и режим доступа. Чаты сгруппированы по папкам в боковой панели; доступны переименование, архив, поиск и перенос в проект на той же машине.

Серверы: CPU/RAM/диск, график сети Linux, IPv4/IPv6, копирование SSH-команды и значений, временный показ пароля, SSH-терминал, ссылка на VNC/консоль провайдера. Показатели и история измерений реальные, без демонстрационных значений. Поиск пространства: **Ctrl/Cmd + K**. Диалоги можно переименовать и архивировать. В SSH-консоли Ctrl+C копирует выделение, а без выделения прерывает команду; Ctrl+V вставляет через штатный механизм терминала. История вывода прокручивается внутри консоли.

**Лимиты агента** доступны рядом с выбором аккаунта и модели в чате, при создании чата и переключении аккаунтов. Codex показывает остаток каждого полученного окна, дату и время сброса, дополнительные кредиты и число доступных сбросов. Данные относятся к выбранному аккаунту, автоматически обновляются и доступны для ручного обновления. Запросы лимитов не запускают модель. Для API-ключей и агентов без такого интерфейса панель явно сообщает об отсутствии данных. OpenCode через ACP передаёт размер занятого контекста и стоимость чата, когда версия агента их поддерживает; это отдельные показатели, а не остаток подписки.

В карточках серверов и компьютеров видны занятые/общие объёмы RAM и диска, доступное место и загрузка в vCPU. На графиках можно выбрать последние 5/15 минут или все сохранённые замеры, посмотреть значение и время указателем, касанием или стрелками. Входящий и исходящий сетевые потоки переключаются в легенде. История содержит до 120 измерений; старые замеры без абсолютных объёмов не дополняются расчётными значениями. Для новых полей метрик домашнего ПК обновите и перезапустите его коннектор.

## Быстрый старт на сервере

Ubuntu/Debian с systemd, amd64 или arm64. Установщик предложит **локальный доступ**, **публичный IP с HTTPS** или **домен с HTTPS**, выдаст логин и случайный пароль, настроит службы и автопродление сертификатов.

```sh
curl -fsSL https://raw.githubusercontent.com/develop-mdv/MayPlane/main/scripts/install.sh -o /tmp/mayplane-install.sh && sudo bash /tmp/mayplane-install.sh
```

Для просмотра перед запуском скачайте скрипт и выполните `bash /tmp/mayplane-install.sh --help` или `--plan`. Из клона репозитория: `sudo bash scripts/install.sh`. Скрипт устанавливает последнюю опубликованную версию; установка из клона использует его `HEAD`.

Для IP/домена нужны свободные и доступные извне TCP-порты **80 и 443**; для домена заранее настройте все A/AAAA-записи. Caddy получает доверенный сертификат и автоматически продлевает его, включая короткоживущие сертификаты IP. Установщик проверяет настоящий HTTPS без отключения проверки сертификата. Посторонние сайты на занятых портах не останавливаются.

Смена логина/пароля и статус сертификата находятся в **Настройки → Доступ к панели**. Подробности, обновление, восстановление доступа, резервные копии и собственный reverse proxy: [docs/self-hosting.md](docs/self-hosting.md).

## Локальный запуск

Нужен Node.js **24+**.

```sh
npm ci
npm run runner:setup
```

Соберите и запустите приложение одной командой запуска:

```sh
npm run build
npm start
```

Откройте [127.0.0.1:8788](http://127.0.0.1:8788) и войдите с данными, выданными `runner:setup`. Порты 8788/8789 слушают только loopback. Данные остаются в `.runner-data/mayplane.sqlite`; `.env.runner` содержит ключ шифрования, его нельзя публиковать.

Для разработки с горячим обновлением запустите API и dev-сервер в двух терминалах:

```sh
npm run runner
npm run dev -- --port 3000
```

Адрес разработки: [127.0.0.1:3000](http://127.0.0.1:3000). Вход тот же; dev-прокси больше не подставляет административный токен.

Не меняйте `MAYPLANE_ENCRYPTION_KEY` у существующей базы: без прежнего ключа её секреты не расшифровать. Для резервной копии используйте SQLite backup API или остановите runner и копируйте базу вместе с WAL/SHM при их наличии; ключ храните отдельно.

Для запуска не из стандартного PATH можно задать абсолютные пути `MAYPLANE_CODEX_BIN` и `MAYPLANE_OPENCODE_BIN`. Установка выполняется по явной кнопке подтверждения. На Linux/macOS оба агента устанавливаются официальными native-установщиками без Node/npm: Codex — в `~/.local/bin`, OpenCode — в `~/.opencode/bin`. Установщик Codex работает без интерактивных вопросов, проверяет загрузку и поддерживает обновление; OpenCode сохраняет уже работающую установку. Настройки и аккаунты сохраняются. На Windows используется npm. Панель находит пользовательские установки без загрузки `.bashrc`, отдельно проверяет версию CLI и готовность аккаунта/протокола, автоматически повторяет проверку после успешной установки. Для SSH рекомендуем отдельного пользователя, а не root.

Модели выбираются из списка с поиском при создании чата и под полем сообщения в существующем чате. Каталог приходит от агента на выбранной машине с учётом рабочей папки и аккаунта: Codex — `model/list` со всеми страницами, OpenCode — ACP config options (для старых версий — ACP models). Уровни reasoning показываются только из возможностей выбранной модели. Пока открыт выбор, список обновляется каждую минуту; кнопка «Обновить» перечитывает его сразу. Установка остаётся настройкой машины; доступ к провайдерам определяется выбранным аккаунтом. Каталог Codex не гарантирует права аккаунта на каждый запрос.

## Домашний ПК без входящих портов

В панели: **Серверы → Подключить ПК → создать код**. На компьютере с копией репозитория и установленными зависимостями:

```sh
npm run connector -- --url wss://control.example.com/api/connector --pair
```

Вставьте одноразовый код по запросу CLI. Он действует 5 минут. Коннектор сохраняет свой отдельный ключ в `~/.mayplane-connector/connection.json`; флаг `--pair` принудительно начинает новое сопряжение. При последующих запусках достаточно `npm run connector` либо того же адреса без `--pair`.

Адрес панели должен быть доступен с компьютера по WSS. Для проверки на одной машине допустим `ws://127.0.0.1:8788/api/connector`. Работают Windows, macOS, Linux. При отзыве подключения в карточке машины старый ключ перестаёт работать. Коннектор должен оставаться запущенным. После сопряжения доступен пользовательский автозапуск: `npm run connector -- --install-service`; отключение — `--uninstall-service`.

Подключение хоста панели, продолжение из CLI/настольного Codex, локальные модели и схема будущего хостинга описаны в [docs/hosted-workspace.md](docs/hosted-workspace.md).

## Аккаунты и разрешения

- **Codex:** в настройках добавьте аккаунт через **Войти с ChatGPT** (ссылка и код устройства) или OpenAI API-ключ. Можно хранить несколько аккаунтов с разными названиями. На машине панели должен быть установлен актуальный Codex. На сервер передаётся access token через app-server; refresh token остаётся в зашифрованном хранилище панели. Доступны `read-only` и `workspace-write`, дополнительные права запрашиваются в чате.
- **OpenCode:** выберите провайдера и предлагаемый им способ OAuth или API-ключ. Список провайдеров и способов входа загружается из OpenCode, установленного на машине панели. Рекомендуется OpenCode 2; OpenCode 1 на целевых серверах поддерживается для совместимых способов входа. Для OpenAI на старом сервере выбирайте **Codex device code (legacy)**, а не token sharing. Инструменты запрашивают разрешение на одно действие.
- **Claude Code:** пока не подключён; адаптер можно добавить в эту же модель машин и диалогов.

Аккаунт машины по умолчанию применяется только к новым чатам. В существующем чате выбор находится под полем сообщения; переключение доступно после завершения хода и сохраняет нативную историю. Для старого чата, созданного со штатным профилем машины и уже получавшего ответы, создайте новый чат с аккаунтом панели. Неподключённый Codex отклоняет отправку до сохранения сообщения, а черновик остаётся при переходе в настройки в этой вкладке.

Для каждого чата создаётся отдельный профиль в `~/.mayplane/agent-profiles/`. Авторизация вне панели не меняется. OpenCode OAuth допускает один активный чат на аккаунт, чтобы не конфликтовали вращающиеся refresh tokens между серверами; API-ключи поддерживают параллельную работу. После хода OpenCode обновлённые токены возвращаются в зашифрованное хранилище, а их копия на машине удаляется. При разрыве связи панель восстанавливает обновлённые credentials перед следующим использованием. Отключение аккаунта очищает секреты панели и профилей; для недоступной машины удаление ставится в очередь до её подключения. Сам профиль и история чата сохраняются.

История, названия диалогов и credentials аккаунтов зашифрованы в SQLite. API никогда не возвращает ключи, access/refresh tokens в браузер. OAuth завершается на странице провайдера; пароль от аккаунта панель не запрашивает. Для подключённых ПК обновите код коннектора и перезапустите его, чтобы появились операции профилей. Это приложение для одного владельца; E2E-шифрование, команды пользователей и RBAC пока не реализованы.

## Удалённое размещение

Используйте установщик из быстрого старта. `npm start` управляет API и production-рендерером как одним приложением. Внешний доступ обслуживает отдельная служба Caddy с HTTPS, редиректом HTTP и автоматическим продлением. API и рендерер остаются на loopback; панель работает от пользователя `mayplane`, прокси — от отдельного `mayplane-proxy` без доступа к базе и ключу.

Вход владельца хранится как scrypt-хеш; браузер получает HttpOnly/SameSite cookie с ограниченным сроком. Пароль можно изменить в настройках или восстановить на хосте через `npm run auth:reset`. Старый `MAYPLANE_TOKEN` больше не даёт вход в запущенную панель. Подключённые ПК используют собственные отзываемые токены WSS; этот канал не требует браузерной cookie.

## Обновление прежнего проекта

Прежние развёртывания называются **Сервисами** и находятся в отдельном разделе. Их серверы, настройки и секреты сохраняются. **Проекты** — только явно добавленные рабочие папки агентов. Автоматически импортированные раньше папки сервисов убираются из проектов; связанные чаты переходят в **Без проекта**, сохраняя историю, нативный ID и прежний рабочий каталог. Новые чаты без проекта начинают работу в домашнем каталоге выбранной машины; Codex по умолчанию использует только чтение. Удаление проекта из списка не удаляет папку и файлы: его чаты остаются без проекта.

Мастер деплоя, переносы и root-LLM-оператор убраны из основного интерфейса. Их старый API и webhooks отключены в обычном runner; обратное включение — только `MAYPLANE_LEGACY_API=true`. Код и данные сохранены для обратимости. Прежняя документация: [docs/legacy-deployment.md](docs/legacy-deployment.md).
